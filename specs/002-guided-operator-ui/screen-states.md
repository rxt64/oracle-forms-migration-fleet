# Annotated Screen States

## 1. Intro

- Persistent header: product identity, actual environment wording, Help and theme commands.
- Working pane: concise purpose, truthful session boundary, one `New migration` action, and a clearly labeled example action.
- No fabricated recent projects until persistent project APIs exist.

## 2. Your Application

- Source choices remain Git clone, ZIP upload, or path description because those are the implemented contracts.
- Git and ZIP explain that the server creates a private session workspace; path description explicitly says no source is copied or connected.
- Validation moves focus to the first invalid field and expands its containing details group if necessary.

## 3. Azure Destination

- React + Java/Spring Boot is shown as the current application route.
- Database choices and planning depth come from bootstrap APIs and retain their executable/unavailable status.
- Subscription, resource group, and region are not shown as selectable until authorized APIs exist.

## 4. Source Checklist

- Required and optional evidence are explained in business wording.
- Selections mean operator-declared inputs for planning, not independently verified facts.
- Trigger source status reads `Source logic retained; not yet converted` when applicable.

## 5. Execution Permissions

- Typed names are visibly labeled planning contacts.
- A persistent boundary states that these fields do not authenticate an actor or authorize writes.
- Sandbox permission and production release remain distinct concepts.

## 6. Review & Plan

- Summary leads with source, destination, and missing requirements.
- Primary action is `Generate migration plan`; adjacent text says it changes nothing.
- Technical names and detailed architecture remain collapsed.

## 7. Activity

- Header answers what is happening and why.
- Structured summary is derived deterministically from the current operation; raw server lines are expandable technical details.
- Closing hides activity and never implies cancellation. During the current request-based implementation, reload/disconnect risk remains visible.

## 8. Results

- Lead statement is either ready for the next implemented step or the highest-priority needs-attention item.
- Generated, built, tested, deployed, and behavior verified are separate labels with evidence links when available.
- Provider/model/token details remain secondary.

## Responsive And Accessibility Annotations

- At 390 px the service rail becomes an accessible compact navigation without page-level overflow.
- Help popovers use an overlay layer and viewport constraints.
- At 200% zoom content reflows; technical tables own any horizontal scrolling.
- Reduced motion disables reveal, cursor, and smooth-scroll animation.
- Forced colors preserves borders, focus, selected controls, and state icons.
